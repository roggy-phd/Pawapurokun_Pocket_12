# パワポケ12 パスワードRAW（106バイト）対照表

パスワード／QRを展開した106バイトの各バイト・各ビットの意味です。パスワード・QR生成ツール（v1.60系）の「アドレス表」と同じ内容で、攻略wiki『ポケ12の仕様』のバイト構造表をもとに、実機での確認結果を追記しています。

- byte番号は1始まり（byte1＝RAWの先頭）
- 各セルは bit7（左）→ bit0（右）の順。能力名は「そのビットが1なら所持」
- 「最小」は、その値未満だとパスワードとして受け付けられない最小設定値（空欄は制約なし）

## 試合中のメモリとの対応（ROM解析で確認）

- 選手データ（1人0xC0バイト、セーブ・メモリ共通）の `+0x28`〜`+0x33` ＝ byte70〜81（野手能力）
- 投手データ（0x2Cバイト、選手データの `+0x44`）の `+0x14`〜`+0x1B` ＝ byte86〜93（投手能力）
- 並べ替えはなく、そのままの配置。32ビットのワードとして読むと、ワードのビットb ＝ byte（基準＋b÷8）の bit（b mod 8）
- 変化球の枠（投手データ `+0x04`〜`+0x0F`）＝ byte42〜53 を系統ごとに「1枠目・2枠目」の順に並べ替えたもの（スライダー1,スライダー2,カーブ1,…,ストレート2）

## パスワード登録時の統合処理（ROM解析で確認）

パスワード／QRから登録するとき、ov17 `0x021A11C4`（投手能力）と `0x021A0D00`（野手能力）で、同じグループの能力が複数立っていると上位だけを残します（例：ノビ◎があればノビ○・△を消す、ローボールヒッターがあればハイボールヒッターを消す）。サクセスから登録した選手には、この処理はかかりません。ROMパッチv26以降で無効化できます。
