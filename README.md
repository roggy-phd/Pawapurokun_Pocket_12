『パワプロクンポケット12』（ニンテンドーDS、ゲームコード VPTJ）の選手パスワード／QRコード生成ツールと、ROMパッチ作成ツールです。

## 注意

- **このリポジトリにはゲームのROM、セーブデータ、エミュレータのステートセーブは含まれていません。** 各自が所有するゲームカードから吸い出したROMに対して使うことを前提としています。
- ROMパッチ作成ツールは、改造していない初版ROM（`PAWAPOKE12_VPTJA4_00.nds`、SHA1 `4327f56f23729a59d44bd170e0ed53a2bb4667dd`）にだけ対応しています。
- 改造は自己責任でお願いします。セーブデータは必ずバックアップを取ってください。

## 内容

| フォルダ | 内容 |
|---|---|
| `password_tool/` | 選手パスワード／QR生成・解析ツール v1.60d（Python／Tkinter） |
| `rom_patcher/` | ROMパッチ作成ツール v31（通常版・max版、Python／Tkinter、標準ライブラリのみ） |
| `rom_patcher/v31unlimited/` | セットFを最大189枠に拡張したv31unlimited版（Python／Tkinter） |
| `tools/` | melonDSのステートセーブを解析するチェッカー（パッチの動作確認用） |
| `docs/` | パスワードのバイト対照表、メモリ上のアドレス一覧、解析メモ、オーペナ検証の結果 |

## 動作環境

- Python 3.8以降（従来版はWindowsで確認）
- パスワードツールのQR出力には `qrcode` / `Pillow` が必要な場合があります（ツールの表示に従ってください）

## ROMパッチ作成ツール（v31）

```bash
python rom_patcher/PowerPoke12_ThirdPitch_v31.py
python rom_patcher/PowerPoke12_ThirdPitch_v31max.py
python rom_patcher/PowerPoke12_ThirdPitch_v31.py 元.nds 出力.nds
```

引数なしで起動すると編集ウィンドウが開きます。コマンドラインでは `--config sets.json` で設定ファイルを指定できます。設定ファイルを指定しない場合は、`--edition normal|max` で初期セットを選べます。

通常版とmax版は同じプログラムで、初期セットと「同じ球種でもLvが違えば別の球として読む」設定の初期値が違います（通常版はOFF、max版はON）。

### 追加球種（第3球種・第4球種以降）

- パスワードbyte92の上位4bit（1〜15）でセットを選びます。パスワード側の変更はありません。v28〜v29で作った選手もそのまま使えます。
- 従来のv31（通常版・max版）は1セットに最大50球（1行目の第3球種6枠を含む）。第4球種以降は、系統ごとの配分が自由です。
- 同じ球種でもLvが違えば複数持てます（追加設定内で同じ球種・同じLvが重複するとエラー）。オリジナル変化球は追加できません。
- 各系統の1行目（第3球種）は、選手がすでに持っている球でも使われます。2つ目以降は、選手の枠と球種もLvも同じ球なら使われません。
- 追加球種が使えるのは、その系統の1番目と2番目の枠が両方埋まっている選手だけです。
- 人間：同じ方向を押すたびに 1番目 → 2番目 → 追加1 → … → 1番目。
- CPU：系統を決めた後、Lvの比で投げ分けます（アクション野球・オーペナとも）。
- 初期セット：通常版は1〜7＝基本5系統の変化球Lv1〜7、E＝ストレートLv7、F＝カットボール／Dカーブ／チェンジアップ／Hシンカー／HシュートLv4＋ストレートLv7。max版はセットFに、スライダー系・カーブ系・フォーク系・シュート系・ストレート系の全球種をLv7で登録しています。
- 設定はウィンドウで保存・読込できます（JSON。v30以前の形式も読めます）。

### 主な機能

| 機能 | 初期値 | コマンドライン |
|---|---|---|
| 追加球種（人間の操作） | 常にON | ― |
| CPU投手も追加球種を使う（アクション野球・オーペナ） | ON | `--no-cpu` で外す |
| 打者の読みの修正（原作バグ修正：投球履歴の番号の取り違え＋オーペナのサインバレ） | ON | `--no-read-fix` で外す |
| オーペナ：追加球種を、打者の読みでは別の球として扱う | ON | `--no-read-sep` で外す |
| 同じ球種でもLvが違えば別の球として読む | 通常版OFF／max版・unlimited版ON | `--read-lv` で有効、`--read-type` で無効 |
| ストレート系の追加球種もストレート待ちとは別の球にする | ON | `--straight-together` でまとめる |
| 「追加球種を別の球として扱う」をOFFにした場合のv29の読み分け | ― | `--no-read-split` で外す |
| 選手能力詳細：特殊能力一覧のスクロール | ON | `--no-scroll` |
| 選手能力詳細：LRで変化球ページ切替（続き・追加球種を6球ずつ） | ON | `--no-pages` |
| 選手能力簡易カード：Yで投法欄⇔追加球種の最高Lv（系統ごとの位置固定） | ON | `--no-card` |
| パス／QR登録時の特殊能力統合の無効化 | すべて止める | `--merge off` / `--merge upgrade` |
| アクション野球：サブポジ○のメイン守備バグ修正 | OFF | `--subpos-fix` で有効化 |
| ペナント：セーブ後にアレンジチームの選手が入れ替わるバグ修正 | ON | `--no-pennant-fix` |
| アクション野球：オリ変の上方向の変化（ポップするストレート）を解禁 | ON | `--no-pop-unlock` |

アクション野球のCPU打者の読みは、追加球種を区別しません（その系統の1番目の球として扱います）。

過去の版（v28・v29）は `rom_patcher/old/` に残しています。変更の詳細は `rom_patcher/CHANGELOG.md` を参照してください。

DSi実機（TWiLight Menu++ / nds-bootstrap）でもセーブできるよう、ROMヘッダのCRCを元のROMと同じ値に保っています（詳細は `rom_patcher/CHANGELOG.md` のv26e）。

## ROMパッチ作成ツール（v31unlimited）

v31をベースに、**セットF（15）だけ追加球種の上限を50枠から189枠に拡張**した版です。セット1〜14は従来どおり50枠まで使えます。

```bash
python rom_patcher/v31unlimited/PowerPoke12_ThirdPitch_v31unlimited.py
python rom_patcher/v31unlimited/PowerPoke12_ThirdPitch_v31unlimited.py 元.nds 出力.nds
python rom_patcher/v31unlimited/PowerPoke12_ThirdPitch_v31unlimited.py 元.nds 出力.nds --config rom_patcher/v31unlimited/v31unlimited_default.json
```

- 初期設定のセットFには、追加可能な通常27球種のLv1〜7をすべて登録しています（27×7＝189枠）。超スローボール、通常ストレートのLv違いも含みます。オリジナル変化球は追加候補に含めません。
- 球種・Lvはウィンドウで編集・削除でき、設定はJSONで保存・読込できます。
- 189枠は追加設定表の枠数です。基礎12枠と重複する組み合わせも含むため、単純に「12＋189＝201種類の独立した球種」になるわけではありません。
- 各系統の先頭追加球は基礎との重複でも使い、2個目以降は基礎と同じ球種・Lvなら使わない、というv31の仕様を維持しています。
- 各系統の基礎2枠が埋まっていること、選手のbyte92上位4bitでセットを選ぶことも従来どおりです。選手にセットFを指定すると、そのROMの拡張セットを使います。
- 既存のセット配置を維持してFの末尾だけを拡張しています。設定表は840→979バイト（1か所あたり139バイト増）で、既存の確保領域内に収まります。
- 従来版と同じく、**改造していない元ROMから作成**します。適用済みv31への重ね掛けはしません。

「unlimited」は従来の50枠制限を解除した名称で、無限に追加できる意味ではありません。また、全Lvを登録すると低Lvの球もCPUの投球候補に入るため、球種数が最大でも、従来の62球種の最強Fより強いとは限りません。

元ROMからの生成・再展開一致検査と、ARM命令を実行した追加球種参照・境界の591件の検査は通過しています。試合動作・DSi実機・オーペナ成績は別途検証が必要です。

検証コードを実行する場合のみ `unicorn` が必要で、パッチ作成ツール自体は標準ライブラリのみで動作します。

## オーペナでの検証結果（ざっくり）

- **v28（原作の読みのバグそのまま）**：最強選手6人×16シーズンで、第三球種を足しても防御率の差は検出されませんでした（どの投手も平均0.7〜0.9）。
- **v31（読みのバグ修正＋追加球種を別の球）**：5シーズン。基本12球種＋セットF 50球の「62球種の最強F」が、防御率0.58・奪三振12.5/9で、5シーズンすべて防御率1位。他の最強5人は防御率0.95〜1.20でした。最強Fとの差は、最強Eを除く4人では有意、最強Eとの比較はp=0.055でした。
- 打者の読みのバグ（番号の取り違え・サインバレ）は、DS甲子園（初期版・ベスト版とも）の自動試合から同じ処理が引き継がれていたものです。

v28の詳細は `docs/openpenna_verification.md`、v31の詳細はnote記事③を参照してください。v31unlimitedの成績検証はまだ含まれていません。
