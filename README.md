## 注意

- **このリポジトリにはゲームのROM、セーブデータ、エミュレータのステートセーブは含まれていません。** 各自が所有するゲームカードから吸い出したROMに対して使うことを前提としています。
- ROMパッチ作成ツールは、改造していない初版ROM（`PAWAPOKE12_VPTJA4_00.nds`、SHA1 `4327f56f23729a59d44bd170e0ed53a2bb4667dd`）にだけ対応しています。
- 改造は自己責任でお願いします。セーブデータは必ずバックアップを取ってください。

## ROMパッチ作成ツール（v31）

```bash
python rom_patcher/PowerPoke12_ThirdPitch_v31.py
python rom_patcher/PowerPoke12_ThirdPitch_v31max.py
python rom_patcher/PowerPoke12_ThirdPitch_v31.py 元.nds 出力.nds
```

引数なしで起動すると編集ウィンドウが開きます。コマンドラインでは `--config sets.json` で設定ファイルを指定できます。設定ファイルを指定しない場合は、`--edition normal|max` で初期セットを選べます。

通常版とmax版は追加球種の仕組みと上限が同じで、初期セットが違います。今回の配布コードでは、「同じ球種でもLvが違えば別の球として読む」は通常版・max版・unlimited版とも初期値ONです。

### 2026-10-12更新：オーペナの先発投手・救援兼任の選択肢を追加

4版（v31 / v31max / v31unlimited / v31unlimited_original_plus）に、救援候補の選択条件を変更する**独立した3つのチェック項目**を追加しました。いずれも初期値OFFで、組み合わせて検証できます。追加球種などの既存機能は維持しています。

| 項目 | CLI | 変更の意味 |
|---|---|---|
| ① 先発上位3枠の時期制限解除 | `--pennant-relief` | 上位3枠がシーズン途中でも救援候補になれるようにする（候補数計算と候補選択の2か所） |
| ② 先発6枠の状態値制限緩和 | `--pennant-starter-fallback` | 先発も救援枠と同じ `B>40` の代替条件を使えるようにする（2か所） |
| ③ 先発投手の救援候補即時確定 | `--pennant-starter-priority` | 救援候補探索で条件を満たした先発投手を、その時点で確定して後続候補の探索を終える（1か所） |

①：ov10 `UcPSearch` `0x0217CED0` / `UcMR_AceNum` `0x0217D050` の `BHS` をNOP化。②：`0x0217CF00` / `0x0217D080` の `BLO` をNOP化。③：`UcPSearch` `0x0217CF4C` の `BLO 0x0217CF58` を `B 0x0217CF6C` に変更します。①の「20試合」は、内部の比較値 `0x14` に基づく暫定的な説明です。②のA・Bは内部値の仮称であり、厳密な意味は未確定です。

**オーペナ実測（同じ開始セーブデータ）**：①②ON・③OFFでは最強Fが**27登板**、①②③ONでは**100登板**。③を加えると救援起用が大幅に増えました。ただし、この比較だけでは①②の必要性や③単独の効果は分かりません。乱数・試合展開が完全一致する保証もありません。

**③はCPUの救援候補選択を大きく変更します。** 翌日の先発予定者を保護する機能はなく、先発投手の酷使や救援投手の出番減少が起こり得ます。①②③はすべて初期値OFF。投手の代打起用は変更していません。詳細な解析・実験結果は別記事にまとめる予定です。

### 2026-10-11更新：オーペナ先発上位3枠の救援制限解除（当時の更新記録）

同名の4種類（v31、v31max、v31unlimited、v31unlimited_original_plus）に、**「オーペナ: 先発上位3枠の救援起用をシーズン全期間で許可」**のチェックを追加しました。**初期値OFF**なので、従来の采配は変更されません。CLIでは `--pennant-relief` を付けた場合だけ有効です。

原作ではCPUの通常救援候補探索 `UcPSearch` が先発上位3枠を除外し、ペナントモード8で残り試合数が20未満のときだけ候補に含めます。ONにすると**この残り試合数による除外だけを無効化**します。対象はoverlay 10のARM命令 `0x0217CED0`（`UcPSearch`）と `0x0217D050`（`UcMR_AceNum`）の2か所です。いずれも `BHS` を `NOP`（`00 00 A0 E1`）に置換します。サクセス等の他モード、救援候補の疲労判定・役割判定、交代を決定する他の分岐は変更しません。したがって登板増加は保証されません。

実施した検証：初版ROM（SHA1 `4327f56f23729a59d44bd170e0ed53a2bb4667dd`）のoverlay 10を展開し、元命令を照合。4種類のパッチ関数で元命令照合を確認しました。**OFF時はパッチ関数を呼ばない実装**です。4種類の完全ROM生成をON/OFF両方で比較する検証、およびmelonDS/DSiでの144試合の登板数比較は未実施です。

### 2026-10-09更新：3版共通の守備対策

名前は **v31 / v31max / v31unlimitedのまま**、アクション野球の守備処理に次の3対策を追加しました。各版の球種設定・上限・既存機能は維持しています。

- **到達計算の終了保証**：捕球地点への到達予測が終わらない場合に備え、到達カウンタが4096に達したら4095を返して終了します。これは上限処理であり、野手の初動や移動計算そのものを修正するものではありません。
- **捕球予測のメモリ解放漏れ対策**：元の処理は3720バイトの作業領域を確保した後に試合状態を確認し、対象外の状態では解放せず終了する経路がありました。状態確認を確保前に行い、不要な確保を避けます。
- **メモリ確保失敗時の書込み防止**：確保結果がNULLなら、ゼロ埋めせず既存の終了経路へ戻ります。

3つとも初期値ONで、画面のチェックまたは個別のコマンドラインオプションで外せます。従来のサブポジ○修正は別の項目で、初期値OFFのままです。

**使いたい版のPythonファイル1本で作成できます。** 未改造ROMから作り直してください。後付けツールを重ねる必要はありません。JSONは球種設定用で、従来と同じ個別設定にしたい場合だけ読み込みます。

今回の守備対策はアクション野球のov3に統合しており、追加領域は計96バイト、既存命令の置換は3か所×4バイトです。守備対策によるARM9・他のオーバーレイの変更はありません。

検証では、3版とも元ROMから生成して再展開し、配置と差分を確認しました。3対策をすべてOFFにした出力は、それぞれの元パッチャーの出力と完全一致します。共通の守備処理については通常・サブポジ○の計306ケースで従来結果と一致し、実際のSDKヒープを使った解放漏れ・確保失敗の試験も通過しています。

**DSi実機での今回の対策は未検証です。** 外野の間への打球で報告されたフリーズについて、今回の不具合が原因だったと確定したものではありません。

### 追加球種（第3球種・第4球種以降）

- パスワードbyte92の上位4bit（1〜15）でセットを選びます。パスワード側の変更はありません。v28〜v29で作った選手もそのまま使えます。
- 従来のv31（通常版・max版）は1セットに最大50球（1行目の第3球種6枠を含む）。第4球種以降は、系統ごとの配分が自由です。
- 同じ球種でもLvが違えば複数持てます（追加設定内で同じ球種・同じLvが重複するとエラー）。オリジナル変化球は追加できません。
- 各系統の1行目（第3球種）は、選手がすでに持っている球でも使われます。2つ目以降は、選手の枠と球種もLvも同じ球なら使われません。
- 追加球種が使えるのは、その系統の1番目と2番目の枠が両方埋まっている選手だけです。
- 人間：同じ方向を押すたびに 1番目 → 2番目 → 追加1 → … → 1番目。
- CPU：系統を決めた後、Lvの比で投げ分けます（アクション野球・オーペナとも）。
- 初期セット：通常版は1〜7＝基本5系統の変化球Lv1〜7、E＝ストレートLv7、F＝カットボール／Dカーブ／チェンジアップ／Hシンカー／HシュートLv4＋ストレートLv7。max版はセットFに、スライダー系・カーブ系・フォーク系・シュート系・ストレート系の全球種をLv7で登録しています。
- 設定はウィンドウで保存・読込できます（JSON。v30以前の形式も読めます）。

## ROMパッチ作成ツール（v31unlimited）

v31をベースに、**セットF（15）だけ追加球種の上限を50枠から189枠に拡張**した版です。セット1〜14は従来どおり50枠まで使えます。

```bash
python rom_patcher/v31unlimited/PowerPoke12_ThirdPitch_v31unlimited.py
python rom_patcher/v31unlimited/PowerPoke12_ThirdPitch_v31unlimited.py 元.nds 出力.nds
python rom_patcher/v31unlimited/PowerPoke12_ThirdPitch_v31unlimited.py 元.nds 出力.nds --config rom_patcher/v31unlimited/v31unlimited_default.json
```

- 初期設定のセットFには、追加可能な通常27球種のLv1〜7をすべて登録しています（27×7＝189枠）。超スローボール、通常ストレートのLv違いも含みます。オリジナル変化球は追加候補に含めません。
- 球種・Lvはウィンドウで編集・削除でき、設定はJSONで保存・読込できます。
- 189枠は追加設定表の枠数です。基礎12枠と重複する組み合わせも含むため、単純に「12＋189＝201種類の独立した球種」になるわけではありません。
- 各系統の先頭追加球は基礎との重複でも使い、2個目以降は基礎と同じ球種・Lvなら使わない、というv31の仕様を維持しています。
- 各系統の基礎2枠が埋まっていること、選手のbyte92上位4bitでセットを選ぶことも従来どおりです。選手にセットFを指定すると、そのROMの拡張セットを使います。
- 既存のセット配置を維持してFの末尾だけを拡張しています。設定表は840→979バイト（1か所あたり139バイト増）で、既存の確保領域内に収まります。
- 従来版と同じく、**改造していない元ROMから作成**します。適用済みv31への重ね掛けはしません。

「unlimited」は従来の50枠制限を解除した名称で、無限に追加できる意味ではありません。また、全Lvを登録すると低Lvの球もCPUの投球候補に入るため、球種数が最大でも、従来の62球種の最強Fより強いとは限りません。

元ROMからの生成・再展開一致検査と、ARM命令を実行した追加球種参照・境界の591件の検査は通過しています。試合動作・DSi実機・オーペナ成績は別途検証が必要です。

検証コードを実行する場合のみ `unicorn` が必要で、パッチ作成ツール自体は標準ライブラリのみで動作します。

## カード野球について

今回の追加球種拡張はアクション野球・オーペナ向けで、カード野球の投球カード生成や読み判定を追加球種対応にする改造は入れていません。

カード野球にも「読み」はありますが、確認した対決計算では球種名・Lvを個別に照合せず、方向グループと第1／第2枠の一致によって0・4・9の加点を行います。投球カード生成も既存の14枠を参照する構造で、追加球種表を列挙しません。この14枠は内部の参照枠数であり、手札の枚数ではありません。

同じグループ・枠にまとめる限り、球種数を増やすだけではオーペナのように「候補が増えて読まれにくくなる」効果を作れません。対応するにはカード生成・分類・読み判定を別途設計する必要があるため、今回の改造範囲には含めていません。

## オーペナでの検証結果（ざっくり）

- **v28（原作の読みのバグそのまま）**：最強選手6人×16シーズンで、第三球種を足しても防御率の差は検出されませんでした（どの投手も平均0.7〜0.9）。
- **v31（読みのバグ修正＋追加球種を別の球）**：5シーズン。基本12球種＋セットF 50球の「62球種の最強F」が、防御率0.58・奪三振12.5/9で、5シーズンすべて防御率1位。他の最強5人は防御率0.95〜1.20でした。最強Fとの差は、最強Eを除く4人では有意、最強Eとの比較はp=0.055でした。
