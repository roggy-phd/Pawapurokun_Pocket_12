# パワポケ12 走者記録NULL参照クラッシュ対策（2026-10-12）

## 対象
`ramDump.bin` と `screenshot02.bmp` で確認した、PC `0x0216D364`・fault address `0x00000004` の **1種類** のクラッシュ。

### 確認した原因（直接要因）
`0x0216D318`（overlay 10）の走者関連更新関数にスロット番号 `3` が渡され、`0x020D0ED8` 内の対応レコード `+4` が NULL。`0x0216D364` の `ldrbeq` で `[0+4]` を読んで Data Abort。後続にもポインタ読み書きがあるので、1命令だけNOPにはしない。

### 実装した対策
関数の入口 `0x0216D318` を分岐させる。`0x020D0ED8[slot]` のレコードと `record+4` の参照先を検査し、どちらかが NULL の場合は関数を呼び出し元へ即時復帰。非NULLなら元の `push {r3-r7,lr}` を実行して原作処理 `0x0216D31C` へ戻る。用いたARM命令11語・44B。

* エントリの置換: `0x0216D318` 4B
* 追加コード: `0x02192DE4`〜`0x02192E0F` 44B（unlimited_original_plusの追加球種テーブル末尾`0x02192DE1`と重ならない）
* **各パッチャーではGUIのチェック（初期ON）で有効化。CLI `--no-runner-null-guard` で無効化。** 救援パッチ①②③やその他のデフォルト挙動は変更しない。
* 提供した既存ROM `v31final.nds` を入力とする保護ROMは、元の設定を維持してこの48Bのみ変更（overlay 10展開後比較）。

## 検証済み
- Python4本の構文チェック。
- 通常版・original_plus版のclean ROMからの生成とoverlay 10再展開一致確認。
- 実使用ROMのoverlay 10展開バイナリとの差分は入口4B＋補助コード44Bのみ。
- ROMヘッダCRCは元の値に維持。

## 重大な制限
これは **NULLが生じた根本原因を修正するものではない**。異常時に走者関連の記録更新を1回スキップするため、失点・走塁・プレー統計等が不整合になる恐れがある。別の場面・別のData Abort（`screenshot01.bmp` のPC `0x01FFAAC8`）を回避する保証もない。ユーザーから動作報告あり。ただし、稀なクラッシュの完全な解消までは未確認。セーブのバックアップを取ること。

本当に根本修正するためには、走者管理レコード `+4` を生成・コピー・消去した命令を特定する追加ログ、または再現直前の状態が必要。今回の32MiBダンプには過去の書込み履歴はない。
