# ROMパッチ作成ツール 変更履歴

対象：パワプロクンポケット12（VPTJ、初版 Rev.00）。すべて改造していない元ROMから作り直す方式です。

## v31（最終版）
- **第4球種以降（追加球種）に対応。** 各セット（byte92の上位4bit＝1〜15）に、第三球種の6枠を含めて最大50の追加球種を持てる。系統ごとの配分は自由（例：フォーク系に44）。表は15セット×56バイト（系統ごとの個数6バイト＋追加球種50バイト、1球1バイト＝Lv×32＋型）。
  - 同じ球種でもLvが違えば別に持てる。同じ系統に同じ球種・同じLvを2つ入れるとエラー。オリジナル変化球は追加球種にできない。
  - 各セット・各系統の**1つ目（ウィンドウの1行目＝従来の第三球種）は、選手がすでに持っている球でも使う**（v29までと同じ。例：枠にシンカーLv7を持つ選手に、セットのシンカーLv4）。v29までに作った選手は、そのままの動き。
  - **2つ目以降は、選手の1番目・2番目の枠とまったく同じ球（球種もLvも同じ）なら使わない。**
  - 条件は従来どおり「その系統の1番目・2番目が両方埋まっていること」。
  - 人間：同じ方向を押すたびに 1番目 → 2番目 → 追加1 → 追加2 → … → 1番目。
  - CPU：系統を決めた後、1番目・2番目・追加のLv比で抽選（追加 i は Li/(L1+L2+追加のLvの合計)）。
  - 選手能力詳細：変化球ページは 1〜6、7〜12（7球以上のとき）、追加球種を6球ずつ。ページ番号は7まで表示（8ページ目以降もLRでめくれる）。
  - 簡易カード（Y）：系統ごとに、使える追加球種の最高Lvを表示。数字の位置は系統ごとに固定（左からスライダー・カーブ・フォーク・シンカー・シュート・ストレート、追加がない系統は空白）。
- **オーペナの打者の読みのバグを修正（初期値ON、`--no-read-fix` で外す）。** 投球履歴の番号の取り違え（IDで記録・コードで判定）と、オーペナだけのサインバレ（予想の前に今の球を履歴に記録）。どちらもDS甲子園から引き継いだ処理。v29の試験オプション（番号の修正だけ）はこれに置き換え。
- **オーペナの読みで、追加球種を別の球として扱う（初期値ON、`--no-read-sep`）。** 同じ打席で前に同じ追加球種を投げたときだけ読まれる。ONのときはv29の読み分けを自動でOFF。
  - 「同じ球種でもLvが違えば別の球」を選べる（ウィンドウのチェック、`--read-lv` / `--read-type`。初期値：max版は別の球、通常版は同じ球種なら同じ球）。
  - ストレート系の追加球種も、初期値ではストレート待ちとは別（`--straight-together` でストレート待ちに読まれる扱い）。
  - アクション野球の履歴は球種コード。
- アクション野球：CPUの追加球種（第三球種）の抽選が1球に2回走っていた問題を修正（v28から）。
- ウィンドウ：各セットの1行目は系統ごとに1つ。「＋」で全球種から選べる行を追加（「−」で削除）。1セット合計50エントリまで（配分は自由）。「通常版／max版の初期セットに戻す」ボタン。マウスホイールでスクロールしたときに、カーソルの下の球種やLvが変わってしまう不具合を修正。
- **通常版とmax版。** プログラムは同じで、初期セット（と読みの初期値）だけが違う（ファイル先頭の `EDITION`、CLIは `--edition normal|max`）。
  - 通常版（`PowerPoke12_ThirdPitch_v31.py`）：v28〜v29と同じ初期セット。
  - max版（`PowerPoke12_ThirdPitch_v31max.py`）：セットFに、スライダー系・カーブ系・フォーク系・シュート系・ストレート系（普通のストレートを含む）の全球種をLv7。シンカー系はなし。
- 設定ファイル：`{"F": {"スライダー系": [["スライダー",7],["Hスライダー",6]]}}` の形式。v30の `["スライダー",7]` の形式もそのまま読める。
- CPUの診断用カウンタは ov10 `0x02192948`。
- 過去の版（v30）は `rom_patcher/old/` へ。

## v30
- **打者の読みの原作バグを2つ修正（初期値ON、`--no-read-fix` で外す）。** v29の `--read-code-fix` を置き換え。
  - 番号の取り違え：直近5球の履歴に「球種ID」が書かれ、判定では「球種コード」と比べていた。オーペナ（ov15 `0x021A3904` / `0x021A4704`）とアクション野球（ov3 `0x020E4F48`）の履歴の書き込みを、コードを書く処理（ov10 `0x02192490`）に差し替え。
  - サインバレ（オーペナのみ）：`UaDefMain` が履歴への追加（`UaDHenkan`）を打者の予想（`UaHitChk`）より先に呼ぶため、予想の2割（20本中4本）が「今投げる球」を当てていた。`UaDHenkan` の呼び出し（`0x021A705C`）では履歴を元に戻して投げた球を覚え（ov10 `0x021924D0`）、`UaHitChk` の直後の空き呼び出し（`0x021A6AB4`）で追加する（ov10 `0x02192558`、状態 `0x021925C0`）。アクション野球はもともと予想が先なので変更なし。
  - v29のBだけ（番号のみ修正）だとサインバレが全投手に効いて投手不利に振れすぎていたため、2つを1つの選択肢にまとめた。
- ウィンドウ全体を縦スクロールできるようにした。タイトルをv30に。
- 過去の版（v28・v29）は `rom_patcher/old/` へ。

## v29
- **オーペナの打者の読みに関する処理を2つ追加。**
  - オーペナの1球ごとの判定（ov15 `UaHitChk`）では、打者が `UcRnd` で次の球を予想し、実際の球と一致すると「読み当たり」としてほぼ打球になる。
  - 第三球種の読み分け（初期値ON、`--no-read-split` で外す）：CPUの第三球種は1種類目と同じ球種コードで投げられるため、1種類目を予想されると読み当たりになっていた。第三球種を投げたときは、L1/(L1+L3)（元の1種類目と第三球種のLv比）の確率でだけ読み当たりにする。第三球種と元の球が同じ球種なら常に読み当たり。比較2か所（`0x021A7764` / `0x021A7790`）→ ov10 `0x02192410`。CPUの第三球種がOFFなら自動でOFF（ウィンドウでは「CPU投手も第三球種を使う」の下に表示）。アクション野球のCPU打者は、投手が球種を選ぶ前（`UcAtkInit`）に予想と曲がりの見込みを決めるので、もともと第三球種を1種類目の曲がりで待っており、変更は不要。
  - `--read-code-fix`（初期値OFF、試験的）：予想に使う直近5球の履歴には「球種ID」が記録されるのに、判定では「球種コード」と比べている原作の食い違いを修正し、履歴にコードを記録する。原作では上位球種（Hスライダーなど）と2種類目の枠の球が履歴からほぼ読まれないため、これをONにするとそうした球を多く持つ投手（最強など）が打たれやすくなる。`0x02168494` の呼び出し3か所（`0x021A3904` / `0x021A4704` / `0x021A705C`）→ ov10 `0x02192490`。
- docstringの記述を実際の初期値に合わせて修正（特殊能力統合の無効化は初期値「すべて止める」、ポップ解禁は初期値ON）。ウィンドウのタイトルをv29に。

## v28
- **アクション野球で、オリ変の上方向の変化（ポップするストレート）を解禁するオプションを追加。**
  軌道計算（ov10）で、縦変化の係数が負のときに0に丸めている（`0x02169E3C cmp r0,#0` / `0x02169E40 movlt r0,#0`）。`0x02169E40` の `movlt` をNOPにして、負の縦変化（＝上方向）がそのまま効くようにした。
  初期値ON（`--no-pop-unlock` で外せる。旧フラグ `--pop-unlock` も受け付ける）。オーペナの自動試合はこの計算を通らないため影響なし。
- 普通のストレートを変化球一覧に表示。
  選手能力詳細（`pages` に含む）：ARM9 `0x020569F8` の `beq`（ストレートを飛ばす分岐）をNOPに。
  簡易カード（`card` に含む）：ov10 `0x021590E4` / `0x0215920C` / `0x02159480` の `cmp r7,#5` を `#6` に（ストレート系だけの特別扱いをなくす）。
- 第三球種の初期セットを変更（v28a）：E＝ストレートLv7のみを追加、F＝カットボール／Dカーブ／チェンジアップ／Hシンカー／HシュートLv4＋ストレートLv7に変更（v25cの「全系統Lv7」から）。

## v27
- 初期設定を整理：ペナントの入れ替わりバグ修正を初期値ONに（`--no-pennant-fix` で外せる）。
- 初期設定で作ったROMは、DSi実機（TWiLight Menu++）でセーブできることを確認済み。

## v26e
- **DSi実機でセーブが保存されない問題を修正。**
  nds-bootstrapは、このゲームの海賊版対策を無効にするパッチ（`apFix/VPTJ-757E.ips`）を「ゲームコード＋ヘッダCRC 0x757E」のときだけ当てる。
  ARM9を作り直すとヘッダCRCが変わってこのパッチが当たらず、セーブが消えていた。
  ヘッダの予約領域2バイト（`0x016`〜`0x017`）を調整して、CRCを元と同じ0x757Eに保つようにした。起動時の「anti-piracy」の注意も出なくなる。

## v26d
- ペナントで、セーブ後にプレイヤーのチームの選手がアレンジチーム1番目の選手に入れ替わるバグの修正を追加（オプション）。
  原因：セーブ時のチーム構築（ov5 `0x020EDAA0`）が、アレンジファイル番号を枠番号に書き換える（`0x020EDB10`）。2回目以降のセーブでそれをファイル番号として読み直していた。
  修正：`0x020EDAD4` から判定関数（ov10 `0x021923F0`）を呼び、書き換え済みのチームは読み直さない。

## v26c
- アクション野球のサブポジ○バグの修正を追加（オプション、初期値OFF）。
  原因：守備位置の不適合度（0〜6）の計算（ov3 `0x021155AC`）で、メインポジション（0）からサブポジ○の1を引いて255になり、上限の6（最低）に丸められる。
  修正：0のときは引かない（`0x02115770`〜`0x02115788`）。
- 特殊能力統合の無効化の初期値を「すべて止める」に。

## v26
- パスワード／QR登録時の特殊能力統合を止めるオプションを追加（ov17 `0x021A11C4` / `0x021A0D00` の書き戻し命令を無効化。「◎と○だけ」「すべて」を選択）。

## v25 / v25c
- v22の「CPU打者の読み」改造を削除（解析の結果、打者の読みではなく配球履歴の一致判定で、改造は投手を不利にしていたため）。
- v25c：初期セット（1〜7：基本球種Lv1〜7、F：全系統Lv7）とGUIの表記を整理。

## v24
- 「読み」改造を初期値OFFに。

## v23
- 総合守備の画面でフリーズする不具合を修正（簡易カードの処理で、投手データのない選手のデータを読んで例外が起きていた）。

## v22
- CPU打者の読みで第三球種を別の球として扱う改造を追加（v25で削除）。

## v21
- CPUの第三球種がオーペナの自動試合でも使われるように（球種選択の最後 `0x021723F4` にもフックを追加）。
- CPU用の状態と設定表を、ov3に頼らずov10側に持つように変更。

## v20
- 表示改善を「スクロール」「変化球ページ」「簡易カード」の独立したオプションに分割。すべて初期値ON。CPUの第三球種も初期値ONに。

## v16〜v19
- 簡易カード（チームアレンジ・オーダー・試合中）で、Yボタンで投法欄を第三球種のLv表示に切り替える機能。
- 顔を消す方式を試したが、名前が消える不具合があったため、v18で顔を消す処理を取りやめ（投法欄の切り替えだけに）。

## 表示改善の追加（Stage D系）
- 選手能力詳細画面で、特殊能力一覧をスクロールできるように（ARM9のフック＋ITCMにコードを追加）。
- LRで、変化球の続き（7〜12球目）と第三球種のページを表示。ページ番号も表示。

## Stage D1
- CPU投手も第三球種を使うように（ov10 `0x02172B64`、選ぶ確率は変化量の比 L1:L2:L3）。

## Stage C
- パスワードbyte92の上位4bitを「第3球種セット番号（1〜15）」として使う方式に。セットごとに6系統の第三球種とLvを設定できる。
- 人間の操作：同じ方向を3回押すと第三球種（1枠目を一時的に差し替えて投げる）。

## Stage A / B
- Stage A：フックが実行されることの確認用。
- Stage B：フォーク系の3回目にチェンジアップLv7を固定で出す試作。
