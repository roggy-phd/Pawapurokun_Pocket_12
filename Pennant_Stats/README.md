# パワポケ12 ペナント成績CSV抽出ツール v3.0

『パワプロクンポケット12』のペナント①・②の**投手成績と打撃成績**をCSVに出力するPythonツールです。通常セーブ（`.sav`）とmelonDS 1.1のセーブステート（`.ml1`～`.ml9`）を読み取れます。入力ファイルは変更しません。

## 動作環境・起動

Python 3.8以降。追加ライブラリは不要です。ZIPをすべて展開してから `pp12_pennant_stats.py` を起動してください。Windowsでダブルクリック起動がうまくいかない場合、`launch_windows.bat` を使うとエラーを確認できます。

## 使い方

1. GUIで `.sav を選択` または `.ml* を選択` をクリックし、入力ファイルを指定します。
2. ペナントの対象を選びます。通常セーブでは「セーブスロット１・２両方」「セーブスロット１のみ」「セーブスロット２のみ」から選びます。ステートでは「現在開いているスロット」を選びます。
3. 「全チーム」「同リーグ1番～6番」「別リーグ1番～6番」から選びます。「同リーグ1～6番」は内部の球団番号1～6、「別リーグ1～6番」は7～12に対応します。これは成績配列内の並び順を表すラベルで、固定の実在球団名ではありません。
4. **抽出データ**を「全て」「投手成績のみ」「野手成績のみ」から選びます。
5. `CSVを出力` をクリックします。「全て」を選んだ場合は `_pitchers.csv`、`_batters.csv` の2ファイルを作成します。

CSVはExcelで開きやすいUTF-8 BOM付き形式です。選手名・球団名・ペナントスロットの列が含まれます。

### コマンドライン

```powershell
python pp12_pennant_stats.py input.sav --cli --slot both --kind both -o season.csv
python pp12_pennant_stats.py input.sav --cli --slot 2 --kind batters -o batting.csv
python pp12_pennant_stats.py input.ml1 --cli --slot active --kind both -o active.csv
```

## 出力項目

**投手成績**：従来の登板、完投、完封、勝敗、セーブ、HP、投球回、自責点、奪三振、与四球、与死球、被安打、ERA、WHIP、K/9など。

**打撃成績**：打席、打数、安打、二塁打、三塁打、本塁打、打点、四球、死球、三振、盗塁、打率、長打率、犠打系の2つのカウンタ、およびレコード位置。打撃成績は各球団26枠（**投手を含む**）のデータです。選手枠は投手1～12・それ以外13～26です。

**現在未対応**：野手の基本能力・特殊能力、投手のシーズン被本塁打。特殊能力などが保存されていないという意味ではありません。

**未解読のまま残している列**：投手の `未解読_0x09`（検証した全576レコードでセーブと完全に同値。
セーブの二重保存か別指標かを判定できないため、名前を断定していません）、投手の `未解読_0x14`（全レコードで0）、
打撃の `未解読_0x09`（全レコードで0）、打撃の `未解読_0x11(盗塁死の可能性)`。

## 対応形式と保存構造

検証済み512KiBセーブでは、成績レコードは以下の位置から始まります（ファイル先頭からのオフセット）。

| ペナント | 投球成績の先頭 | 打撃成績の先頭 |
|---|---|---|
| ① | `0x182C2` | `0x180EE` |
| ② | `0x1F3C2` | `0x1F1EE` |

1球団あたり `0x308` バイト。前半に26人×18バイト（`0x12`）の打撃成績、その後に12人×22バイト（`0x16`）の投手成績が続きます。①②の両方が保存されている場合は、打撃成績624レコード、投手成績288レコードを抽出します。

### 打撃成績18バイトレコード

| オフセット | 内容 |
|---|---|
| `+0x00` | 打席数（16bit） |
| `+0x02` | 安打（12bit） |
| `+0x04` | 二塁打（12bit） |
| `+0x06` | 三塁打（8bit） |
| `+0x07` | 本塁打（8bit） |
| `+0x08` | 犠打（SH） |
| `+0x09` | 未解読（検証した2セーブの全1248レコードで0） |
| `+0x0A` | 打点（12bit） |
| `+0x0C` | 三振（12bit） |
| `+0x0E` | 四球（8bit） |
| `+0x0F` | 死球（8bit） |
| `+0x10` | 盗塁（8bit） |
| `+0x11` | 未解読（盗塁死の可能性。盗塁と相関 r=0.31、合計は盗塁の約50%） |

打数は `打席−四球−死球−犠打−(+0x09)` で復元します。`打率=安打÷打数`、
`長打率=(安打+二塁打+2×三塁打+3×本塁打)÷打数`。

`+0x08` を犠打と判断した根拠は打席あたりの比率です。投手枠が 0.057／打席、野手枠が 0.031／打席で、
投手のほうが犠打を決める実際の野球と一致します。本塁打上位の打者にも同程度あり、犠飛の分布とは異なります。

出塁率は `(安打+四球+死球)÷(打数+四球+死球)`、OPS はその出塁率と長打率の和です。**犠飛が保存されていない
前提**での算出なので、列名にその旨を入れています。犠飛が実際には別の場所に記録されている場合、
わずかにずれます。

## 検証

ペナント②の巨人・小笠原は**568打数155安打、32二塁打、25本塁打、75打点、打率.273**、ラミレスは**555打数154安打、22二塁打、32本塁打、84打点、打率.277**。ゲーム画面と一致しました。

ペナント②の `.sav` と、同じ場面のmelonDS 1.1 `.ml1` を比較し、全12球団・26枠＝312打撃レコードについて、ステート保存位置とスロット表示以外のCSV項目が一致することを確認しています。

### リーグ内の突き合わせ検証（v3.0で追加）

リーグ内で試合が完結していれば、投手の被記録と打者の記録は一致するはずです。検証した2本のセーブ・
3つのペナントデータすべてで、次の4項目が**1件の差もなく一致**しました。

| 投手側 | 打者側 | ペナント①(前) | ペナント①(後) | ペナント② |
|---|---|---|---|---|
| 被安打 | 安打 | 12743 / 12743 | 12743 / 12743 | 13134 / 13134 |
| 奪三振 | 三振 | 10766 / 10766 | 10766 / 10766 | 10798 / 10798 |
| 与四球 | 四球 | 4319 / 4319 | 4319 / 4319 | 4468 / 4468 |
| 与死球 | 死球 | 614 / 614 | 614 / 614 | 626 / 626 |

打撃レコードのオフセット解読が正しいことの裏付けになります。投球アウト数と打撃から推定したアウト数の差
（ペナント①で803、約1.7%）は、盗塁死や併殺の走者アウトぶんとして妥当な範囲です。

## 選手名について

編成球団はセーブ内の選手登録名を取得します。既存球団はROMから取り出した2009年の標準選手名表を同梱して参照します。独自文字コードによる漢字変換には一部未修正の文字が残っている場合があります。チーム編成やROMを変更したセーブでは名前の一致を保証しません。

## v3.0での変更

- 投手 `+0x09` の列名を「セーブ（別カウンタ）」から `未解読_0x09(本データではセーブと一致)` に変更。
  全576レコードでセーブと同値でしたが、セーブの二重保存と断定する根拠がないためです。
- 投手 `+0x14` を「予約領域（未使用候補）」から `未解読_0x14` に変更。全レコードで0ですが、
  未使用と断定する根拠はありません。
- 打撃 `+0x08` を `犠打`、`+0x09` を `未解読_0x09`、`+0x11` を `未解読_0x11(盗塁死の可能性)` に変更。
- 出塁率とOPSを算出するようにしました（犠飛が保存されていない前提。列名に明記）。
- 通常セーブで既定位置に成績配列が無い場合、走査で見つかった配列へフォールバックするようにしました。
  その場合は「スロット番号の対応は未確認」と警告を出します。他スロットのデータを流用することはありません。
- `pp12_core.py` に残っていた旧v2.4のGUIを削除。直接起動すると案内を出して終了します。
- 未使用のimportと変数を整理。

## 注意

セーブやステート内の成績を読み出すだけのツールです。異なるROM版・セーブ形式、未使用のペナントスロットは未検証です。エラー時には値を推測して補完しません。

### セーブスロットに成績がない場合

- 「セーブスロット１のみ」「セーブスロット２のみ」で対象の成績配列が確認できない場合は、CSVを作成せずエラーを表示します。
- 「セーブスロット１・２両方」を選んだとき、片方だけ確認できた場合は**確認できたスロットのみ出力**し、警告を表示します。両方とも確認できなければエラーです。
- 成績配列を確認できない理由は、未使用・ゲーム内で未保存・非対応セーブ形式等が考えられます。このツールだけで「未使用」と断定はしません。誤って別スロットのデータを割り当てることはありません。
